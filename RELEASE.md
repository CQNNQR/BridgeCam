## Release Strategy Overview

**Immediate goal:** Publish BridgeCam v1.0 as a single `.exe` installer on GitHub Releases with clear instructions so that anyone can download, install, and start using their phone as a webcam in under 2 minutes.

**Long-term goal:** Host everything on `bridgecam.com` — a clean landing page, download links, documentation, and potentially an auto-update endpoint.

**Principles:**
- One download, one installer — no multi-step setup
- Works out of the box on Windows 10/11
- VB-Audio Cable bundled or auto-installed (for virtual mic)
- Virtual camera driver registered automatically during installation
- Signaling server runs in the cloud (already deployed on Render)
- Zero user accounts, zero telemetry, zero tracking

## Phase A: Update Service

### Current State
- Tauri updater plugin is enabled (`tauri-plugin-updater` in `Cargo.toml`)
- Desktop app checks `/update/latest` on the signaling server (currently returns 404)
- `checkForUpdates()` in `main.js` supports both Tauri's native updater and a manual manifest fallback

### What Needs to Happen

| # | Task | Description |
|---|------|-------------|
| A.1 | **Create update manifest endpoint** | Serve a JSON manifest at `https://bridgecam.onrender.com/update/latest` (or a dedicated endpoint) returning `{ version, url, signature, notes }` matching Tauri's updater schema |
| A.2 | **GitHub Releases as update source** | Point the update manifest's `url` field to the GitHub Releases download URL for the `.msi` or `.nsis.exe`. Tauri's updater downloads and applies it automatically |
| A.3 | **Code signing (optional but recommended)** | Use Tauri's `TAURI_SIGNING_PRIVATE_KEY` to sign update bundles. Without this, the updater still works but shows a "not verified" warning |
| A.4 | **Version bump workflow** | Create a simple script or CI step that bumps `tauri.conf.json` version, builds, signs, uploads to GitHub Releases, and updates the manifest |
| A.5 | **Migrate to Tauri's built-in updater endpoint** | Configure `tauri.conf.json` → `plugins.updater.endpoints` to point at `https://api.github.com/repos/OWNER/BridgeCam/releases/latest` — this eliminates the need for a custom manifest server entirely |

### Implementation Notes
- Tauri v2 supports GitHub Releases as a native update source. The simplest path:
  ```json
  // tauri.conf.json
  "plugins": {
    "updater": {
      "active": true,
      "endpoints": ["https://github.com/OWNER/BridgeCam/releases/latest/download/latest.json"],
      "dialog": true,
      "pubkey": "<YOUR_PUBLIC_KEY>"
    }
  }
  ```
- The `latest.json` file is auto-generated by `cargo tauri build` and should be uploaded alongside the installer to each GitHub Release

## Phase B: Single-Exe Packaging

### Current State
- Tauri builds produce both `.msi` (WiX) and `.exe` (NSIS) installers
- Virtual camera DLL (`BridgeCamMFSource.dll`) is built separately via CMake and deployed manually
- VB-Audio Cable (virtual mic) requires separate manual installation by the user
- `register.bat` / `deploy.ps1` scripts handle DLL registration

### What Needs to Happen

| # | Task | Description |
|---|------|-------------|
| B.1 | **Bundle virtual camera DLL into NSIS installer** | Add the x64 and x86 `.dll` files as Tauri external resources (`tauri.conf.json` → `bundle.resources`). NSIS `beforeInstallScript` copies them to `System32`/`SysWOW64` and runs `regsvr32` |
| B.2 | **Bundle VB-Audio Cable installer** | Include `VBCABLE_Setup_x64.exe` as a resource. NSIS `afterInstallScript` runs it silently (`/S` flag) or prompts the user. **Alternative:** detect if VB-Audio is already installed and skip. **License note:** VB-Audio Cable is donationware — redistribution requires contacting VB-Audio (Vincent Burel). Check their license terms before bundling |
| B.3 | **One-click NSIS installer** | The final installer flow: (1) Install Tauri app to `Program Files`, (2) Register virtual camera DLL, (3) Install/detect VB-Audio Cable, (4) Create Start Menu + Desktop shortcuts, (5) Launch BridgeCam |
| B.4 | **Uninstaller cleanup** | NSIS `afterUninstall` should: unregister DLL (`regsvr32 /u`), deactivate virtual camera, remove SHM files from `C:\ProgramData\BridgeCam\`, remove registry entries |
| B.5 | **GitHub Release automation** | CI/CD (GitHub Actions) workflow: `cargo tauri build` → upload `.exe` + `latest.json` to GitHub Releases. Tag-based triggers (`v1.0.0`, etc.) |
| B.6 | **README download instructions** | Clear "Download & Install" section at the top of README: (1) Go to Releases, (2) Download `BridgeCam-Setup-x.y.z.exe`, (3) Run installer, (4) Launch BridgeCam, (5) Scan QR with phone |
| B.7 | **Portable mode (optional)** | A `.zip` distribution for users who don't want an installer. Contains the exe + DLLs + a `register.bat` for manual setup |

### NSIS Custom Script Reference
```nsi
; tauri.conf.json → bundle.nsis.installerIcon / headerImage / etc.
; Custom NSIS scripts go in:
;   beforeInstallScript: runs before Tauri files are extracted
;   afterInstallScript:  runs after extraction, before finish page
;   beforeUninstallScript / afterUninstallScript: cleanup

; afterInstallScript example:
!macro customInstall
  ; Register virtual camera DLL (64-bit)
  SetRegView 64
  CopyFiles "$INSTDIR\resources\BridgeCamMFSource_x64.dll" "$SYSDIR\BridgeCamMFSource.dll"
  nsExec::ExecToLog 'regsvr32 /s "$SYSDIR\BridgeCamMFSource.dll"'

  ; Register virtual camera DLL (32-bit for 32-bit apps)
  SetRegView 32
  CopyFiles "$INSTDIR\resources\BridgeCamMFSource_x86.dll" "$WINDIR\SysWOW64\BridgeCamMFSource.dll"
  nsExec::ExecToLog 'regsvr32 /s "$WINDIR\SysWOW64\BridgeCamMFSource.dll"'
!macroend
```

## Pre-Release Checklist

A final checklist to run through before clicking "Publish" on the GitHub Release:

```
□ Run `cargo tauri build` — clean build, no warnings
□ Run `npm audit` in server/ — 0 vulnerabilities
□ Run `cargo audit` — 0 vulnerabilities
□ Test installer on a CLEAN Windows 10 VM (no dev tools installed)
□ Test installer on a CLEAN Windows 11 VM
□ Virtual camera shows up in Zoom (Settings → Video)
□ Virtual camera shows up in OBS (Sources → Video Capture Device)
□ VB-Audio Cable "CABLE Output" appears as mic in Zoom
□ Phone connects via QR code (Chrome Android)
□ Phone connects via QR code (Safari iOS)
□ 1080p 30fps streaming for 30+ minutes — no crash, no memory leak
□ Audio piping works — phone mic audible in Zoom on other end
□ Auto-update: bump version, build, verify update dialog appears
□ README download section has correct link to latest release
□ LICENSE file is GPLv3 full text
□ PRIVACY.md exists and is accurate
□ THIRD_PARTY_LICENSES.txt is generated and up to date
□ No API keys, tokens, or secrets in git history

□ GitHub Release created with tag v1.0.0
□ Release notes written (changelog since last release)
□ Installer binary attached to release
□ latest.json attached to release (for auto-updater)
```
